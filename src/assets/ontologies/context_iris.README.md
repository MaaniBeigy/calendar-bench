# context_iris.json, context-feature IRI dictionary

A curated dictionary of IRIs that drop into `context_features.yaml` (or any persona-config), and the canonical target for `context_links` references from `HealthTasks_2026.05.19.json`. Generated by `src/data/build_context_iris.py`.

## Scope (momentary contexts only)

This file lists **momentary** context features. A user can move in and out of these throughout the day, and each value can carry duration, episode count, and temporal_patterns the same way an event does.

What **is not** in this file:

- **Stable user traits** (Big Five profile, demographics, identity), those live in persona `characteristics:` and are sampled once per user. The file does include the *state* of currently behaving in line with a trait (`trait_state`).
- **Day-part / day-type** (`morning`, `Saturday`), already covered by `environment.yaml time_windows` and the W3C OWL-Time vocabulary.
- **Measurement classes** (EFO `<trait> measurement`), these are about *measuring* a trait, not about the user's current state. They are excluded.
- **Personasonto umbrellas**, retired. They were thin classes without rich subclasses.

## Role of this file

**Forward lookup**: the persona simulator gets a momentary context (slug or IRI) and pulls the matching entry to instantiate a context feature.

Each entry is keyed by `(category, slug)` and exposes one canonical `iri`. Entries that name a concept also expressed in two categories (e.g. `behavioural_intention` belongs to both `behaviour_state` and `goal_intention`) keep a local `cb-namespace` IRI in the secondary category and a `same_as` array pointing at the canonical BCIO or EFO IRI. See the `same_as` schema below.

## `delivery_style` schema (Bergram 2022)

Each entry is one of the 10 digital-nudging patterns from Bergram, Djurica, Sundar & Aleta (2022). The patterns describe the *mechanism* by which a recommendation steers behaviour, not the content of the recommendation. A HealthTask normally cites 1 to 3 patterns based on what its mechanism is.

The 10 patterns: `default`, `reinforcement`, `social`, `disclosure`, `friction`, `decoy_deception`, `feedback`, `warning`, `scarcity`, `commitment`.

`decoy_deception` is included for completeness but never cited by tasks: Bergram et al. flag it as ethically inappropriate for health coaching, and we keep that exclusion in practice.

```json
"default": {
  "iri": "https://w3id.org/calendar-bench/context#delivery_style/Default",
  "label": "default-based delivery",
  "source": "Bergram 2022",
  "definition": "The recommendation pre-selects the desired option so the user receives the healthy choice unless they actively change it (opt-out structure). Use when the task is a one-shot substitution / setting / swap where flipping the default is the mechanism (Bergram et al. 2022, §4.1)."
}
```

## `same_as` cross-references

Eight concepts naturally belong in two categories at once (a behavioural intention is both a `behaviour_state` and a `goal_intention`; intrinsic motivation is both a `behaviour_state` and an `sdt_regulation`; anxiety is both a `mood_emotion` and a `stress` cue). Each pair has one **primary** entry that owns the canonical BCIO or EFO IRI, and one **secondary** entry that uses a local `cb-namespace` IRI plus a `same_as` array pointing at the canonical IRI. The TTL generator renders `same_as` as `owl:sameAs` triples.

## Linking from HealthTasks

`HealthTasks_2026.05.19.json` carries one `context_links` block per task with eight keys that resolve into this dictionary:

```json
"context_links": {
  "delivery_style":     ["default", "reinforcement"],
  "mood_emotion":       ["happiness", "satisfaction", "..."],
  "energy_state":       ["feeling_tired", "feeling_energetic", "..."],
  "physiological":      ["feeling_of_hunger", "..."],
  "stress":             ["distress_minimisation_behaviour", "..."],
  "location":           ["home", "office", "..."],
  "social_context":     ["alone", "family_environmental_system", "..."],
  "weather_environment":["weather_opportunity", "..."]
}
```

The BCIO theory block (`ttm_process`, `bct`, `behaviour_state`, `capability_opportunity`, `goal_intention`, `sdt_regulation`) is also carried in `context_links` and resolves into this dictionary the same way.

## `trait_state` schema

Each entry represents the user *currently behaving in a way characterised by* a personality dimension. Use these as momentary contexts (with durations and temporal patterns), not as stable trait scores.

```json
"extraverted_state": {
  "iri":   "http://www.ebi.ac.uk/efo/EFO_0004317",
  "label": "extraversion",
  "source": "EFO",
  "polarity": "high",
  "instrument": "BFI",
  "comment": "User is currently behaving in a high-extraversion manner (talkative, sociable, energetic)."
}
```

Big Five coverage: **extraverted / introverted**, **agreeable / antagonistic**, **conscientious / careless**, **emotionally_reactive / emotionally_stable**, **open_to_experience / conventional**, paired high/low states (10 values).

TCI coverage (Cloninger): **temperament**, novelty_seeking / routine_oriented, harm_avoidant / risk_tolerant, reward_dependent / reward_independent, persistent / easily_discouraged. **character**, self_directed / blaming, cooperative / uncooperative, self_transcendent / individualistic. 14 values.

Adjunct momentary expressions (OCHV): **impulsive_state, sensation_seeking_state, optimistic_state, pessimistic_state**. 4 values.

IRI policy:

- `EFO_0004317` (extraversion) is the only Big-Five trait class with a clean published OWL IRI; it is used by `extraverted_state` (polarity `high`). Every other Big-Five facet, including the introverted-low pair, falls back to a local IRI under `https://w3id.org/calendar-bench/context#trait/<TraitDimension><High|Low>` (so `introverted_state` is `…#trait/ExtraversionLow`).
- TCI subscales have no widely-adopted ontology home, so they also use the local namespace.
- OCHV (UMLS-derived) supplies `impulsivity`, `sensation seeking`, `optimism`, `pessimism`, and `uncooperativeness`.

## `theory_mappings` schema (behaviour_state, capability_opportunity)

Each entry in these two categories carries:

```json
"theory_mappings": {
  "tdf_domain":     ["..."],
  "comb":           "...",
  "hapa":           "...",
  "ttm_process":    "...",
  "ttm_stage":      "...",
  "sdt_regulation": "...",
  "sdt_need":       "..."
}
```

Field reference:

- `tdf_domain`: Atkins 2017 Table 1, v2 14 domains.
- `comb`: physical_capability / psychological_capability / physical_opportunity / social_opportunity / reflective_motivation / automatic_motivation (with `_low` suffix for deficit variants).
- `hapa`: intention / action_self_efficacy / action_planning / coping_planning / action_control / maintenance_self_efficacy / recovery_self_efficacy.
- `ttm_process`: Prochaska & DiClemente 10 processes.
- `ttm_stage`: precontemplation / contemplation / preparation / action / maintenance.
- `sdt_regulation`: amotivation / external / introjected / identified / integrated / intrinsic / autonomous_umbrella.
- `sdt_need`: autonomy / competence / relatedness.

null on any field = "this IRI is silent on that theory layer".

## GraphRAG registration

The ontologies used here are registered in `src/graphrag/ontology_metadata.py` and pulled into Neo4j by the GraphRAG import scripts. EFO covers the extraversion trait IRI and the broader GWAS/cohort vocabulary, and OCHV supplies the consumer-health trait expressions (impulsivity, optimism, pessimism, sensation seeking, uncooperativeness). MFOEM, BCIO, ENVO, OMRSE, COPPER, and ADDICTO ground the remaining categories.

Test queries for each source live in `tests/test_rag.py`. The EFO query uses GWAS-cohort labels ("extraversion", "personality trait", "Temperament and Character Inventory") that do not get shadowed by BCIO's broader behavioural-disposition entries.
